**What changes.**
- *`src/consumer-declaration.ts`* (a leaf, imports nothing from the package): the grammar is one line per option, `Consumer-declaration:` then `<owner/repo>:<path> <key>=<value>`, `<key>` a dotted path into the JSON file. `parseConsumerDeclarations` returns `{ declarations, errors }`, never a boolean. A line that begins with the keyword and does not fit is an error naming its line number and text, never skipped; `none -- <reason>` after the keyword is no declaration and no error (a `none` with no reason is an error); a backticked mention in prose is not a line. Repo and path are a closed character set because they go into a request URL.
- *`src/closes-mismatch-check.ts`*, a fourth direction beside the third: `consumerDeclarationReport` (pure, over an injected `ConsumerFileReader`, as `lookupClosingIssues` is injected) refuses when the PR has a declaration line and a `Closes` that names a row, and any key is not the value in the consumer's file on its default branch. The message names the file, the key, what it holds now (or that it is absent) and the two ways out. A file that cannot be read, or is not JSON, is a refusal naming that. `Closes: none -- <reason>` reads nothing and passes; malformed lines are still named. Each distinct file is read once. The source of the text is the file the PR adds (`acceptanceSourceOfThisPullRequest`), and a source with no text (refused, duplicate) is a named skip, never "declares nothing".
- *The one direct call:* `lookupConsumerFile`, one `gh api repos/<repo>/contents/<path>` with no `ref` (the default branch), raw. **The gh-call baseline of `src/closes-mismatch-check.ts` rises 2 -> 3 by `ceo` ruling (agent-org#838, option 1); the call moves into the code-host port when its adapter is built. It is not a fifth ticket operation (ADR 0046 Decision 3).** `docs/gh-call-baseline.json` and `docs/gh-call-inventory.json` are regenerated in this PR.
