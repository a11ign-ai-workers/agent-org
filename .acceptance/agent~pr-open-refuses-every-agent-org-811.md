`pr:open` no longer refuses every worker's pull request into a review-only lane: `gh api user` answers an App's installation token `HTTP 403`, so the login is read from the GraphQL `viewer` when it fails (a11ign/agent-org#811, from a11ign/a11ign#4910).

Closes a11ign/agent-org#811

## What changes, and why

- **`loginThrough(gh)`** (`src/pr-open.ts`) is what `defaultLogin` now is: `gh api user --jq .login`, and when that fails or answers nothing, `gh api graphql -f query='{ viewer { login } }'`. A user token pays one call, as before. An identity neither read answers throws with both failures named, so `authorshipRefusal` still refuses ("could not say who is opening it", #3254): unreadable is never "not the owner".
- **stderr is piped**, so the 403 is no longer printed above the pass on every worker's PR, and the refusal quotes `gh`'s own line (`Resource not accessible by integration (HTTP 403)`) rather than `Command failed: gh api user ...`.
- **Measured, from this worker session** (installation token, 2026-10-11): `gh api user --jq .login` printed `gh: Resource not accessible by integration (HTTP 403)`; `gh api graphql -f query='{viewer{login}}' --jq .data.viewer.login` printed `a11ign-workers[bot]`. The candidate "the role `host/gh` minted the token for" was not needed: the wrapper knows a role, not a login, and the login is what the lane map is keyed on.

## Anything a reviewer should be sceptical of

- **`ROLE_LOGIN.ceo` (`src/lane-ownership.ts`, outside this row's Region) does not name the managers App, and `ceo` is already on it.** `host.json`'s `github.identity` declares `managers` (ceo, product-manager, orchestrator) as `github-apps`, and `~/.local/bin/gh` renders `APP_ROLES=scheduler workers managers`. Measured from a public read: App id `5267143`, which is `managers`' declared `appId`, is the slug `a11ign-managers`, so a leads session's `viewer` login is `a11ign-managers[bot]` (inferred from the slug; not read from a leads session, which this one is not). `ROLE_LOGIN.ceo` is `a11ign-ai-leads` only. **Before this change the 403 refused a leads session's workflow PR too, by accident; after it, that PR passes `pr:open`'s authorship check**, and so would `arm-pr` and the sweep, which read the same map through `ownsReviewOnlyLane`, unless it names the bot. This change does not treat "an App login" as "not an owner": the comparison is against the role map, and the map is missing an entry. The follow-up is one entry in `ROLE_LOGIN.ceo` (`src/lane-ownership.ts`) plus a pin that every declared `github-apps` role's login is accounted for; it is filed as a11ign/agent-org#816, and **should land with or before this PR**. `work-gate.ts`'s own `ROLE_LOGIN` copy is the CODEOWNERS login (who must review) and needs no change: a PR authored by the bot is already reported there as missing the owner's review.
- **The fallback fires on any `api user` failure**, not only a 403. A 401 from a dead token fails the viewer read too and refuses as before; a transient error costs one extra GraphQL point and answers truthfully, since the viewer is the same identity `gh pr create` will author as.
- **`docs/gh-call-inventory.json` changes by one call site.** `loginThrough`'s GraphQL read is a new `api graphql` shape in `src/pr-open.ts` (calls 391 to 392, `api graphql` 37 to 38); the first push missed it and CI's `suite` failed `gh-call-inventory.test.ts` on it. Regenerated with `node src/packaging/gh-call-inventory.ts`; the diff is those three lines and nothing else, and the file passes with the two acceptance files (39 of 39).
- **Checks run, and not run.** `npx tsc --noEmit -p tsconfig.json` exits 0 at this head (measured here). `pnpm run lint` and `pnpm run verify` were not run in this worktree, whose private `node_modules` is the rstest/typescript subset only; CI's `lint` and `gate` are the verdict for those.
