The claim-stall pass paid for a held row's git reads whether or not its reading asked for them. `claimFactsFrom` ran `rev-parse --verify` and `log -1` for the branch and for `origin/<branch>` while building every held row's facts (the comment above it said the costly facts were thunks; two of the four were not), and `facts.file()` and `facts.work()` re-ran `git status` / `git rev-list` for each reading that asked. Now `commit`, `push`, `file` and `work` are all thunks that `claimFactsFrom` memoises (`once`), so a row costs only the reads its reading reaches and each at most once per tick; `performRelease`'s fresh re-read still goes through `holderWorkAtRisk` itself, unmemoised. `ClaimFacts.commit`/`push` change from `number | null` to `() => number | null`, and `movesOfTick` (the home tracker's `onFacts`, the one reader that asks every row, for `org-health` and `blockerClearedOrders`) calls them and names a row whose git would not answer in `skipped`.
