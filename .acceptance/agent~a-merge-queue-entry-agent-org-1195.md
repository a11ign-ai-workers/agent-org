A merge-queue entry that stands `AWAITING_CHECKS` for more than ten minutes with no `merge_group` run on its group's head commit is named by the gate, dequeued and armed again ONCE with no model turn, recorded on the pull request, and counted per day (agent-org#1195, a11ign#928: "the merge queue sat for 50 minutes on an entry whose CI never started"). A repeat on the same pull request is not re-queued a second time: it is raised as the `queue-entry-no-run` org-health signal to `product-manager` and `ceo`. `queue-head-age` carries the position-1 entry's age, so a stall of this shape shows at ten minutes.

**Decisions the row left to the engineer, said so.**
- **Flag OFF reads and writes nothing**, the detector's reads included. The signals therefore exist only while the flag is on; turning it on is the observation, and its canary hour watches `approved-unqueued` and `blind-ticks`.
- **Confirmed on a second tick** (`QUEUE_ENTRY_NO_RUN_CONFIRM_MS`, 60 s): an entry that has stood ten minutes since enqueue may have become `AWAITING_CHECKS` seconds ago (a group built when the entry ahead merged), or a runs list may lag a run's creation; one tick of "no run" would dequeue it and rebuild every group behind it. The row's "more than ten minutes" holds; the act is on the tick after the entry is first seen.
- **The once is keyed on the pull request and written before the act**, with a 24-hour memory. The row says "keyed on the group head sha", but a re-queue builds a NEW group with a new sha, so a sha key could never see its own repeat; the sha is recorded beside it. An attempt that failed spends the one, and the repeat's reading says what it came to.
- **Counted in `queue-entry-no-run.json` (`days`), not in the failure ledger**: `class-repeat` reads that ledger over all time and files a class row for a kind with two distinct refs, so two re-queues of two pull requests would file a class row for the measurement itself.
- **Only the home repository's queue is read.**

**NOT shown, said plainly.** The dequeue was not run against a live entry (the only entry that would show it is a real pull request). Its shape was read from GitHub's GraphQL schema and recorded on the row first (comment 6128639668): `dequeuePullRequest(input: { id })`, the pull request's node id. Whether it clears the pull request's auto-merge is not known; the re-arm goes through `armMerge`, whose own settle-and-read-back counts "already armed" as armed, and a dequeue that arms nothing is recorded as such and is the repeat's reason. The flag ships OFF, so the first live use is the canary's watched hour.
